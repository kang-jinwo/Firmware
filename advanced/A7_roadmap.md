# A7. 프로젝트 이후: 어디로 더 파고들 것인가

프로젝트와 A1~A6을 마치면 "PC 위의 시뮬레이션에서 펌웨어의 구조와 메모리를 이해했다"까지 온 것이다.
여기서부터는 **실제 칩에서, 운영체제 없이, 그리고 여러 작업과 함께** 가는 길이다.

아래는 추천 순서다. 전부 하라는 것이 아니라, 지도를 주는 것이다. 편입 준비와 학기 중 여유를 보고 고른다.

## 1단계. C와 메모리를 책으로 한 번 정리한다

실습으로 본 것을 체계로 묶는다.

| 자료 | 무엇을 | 어디를 |
|---|---|---|
| **Computer Systems: A Programmer's Perspective** (Bryant, O'Hallaron. 번역서 "컴퓨터 시스템") | 이 폴더의 내용 전체의 교과서. 시스템프로그래밍 과목에서 널리 쓰인다 | 2장 (정수·실수 표현) → 3장 (기계어, 스택 프레임) → 7장 (링킹) → 9장 (가상 메모리, malloc 구현) |
| **The C Programming Language** (Kernighan, Ritchie) | 얇고 정확한 C 책 | 5장 (포인터와 배열), 6장 (구조체) |

읽는 법: A1~A6에서 "왜 그런지 끝까지는 모르겠다"고 적어 둔 것을 들고 해당 장을 찾아 읽는다. 처음부터 끝까지 읽으려 하면 지친다.

CS:APP 3장을 읽으면 M8에서 `objdump` 로 본 기계어를 한 줄씩 읽을 수 있게 된다. 9장 끝의 malloc 구현 과제는 A4의 풀을 일반적인 크기로 넓힌 것이다.

## 2단계. 실제 칩에서 돌린다

**목표: 이 프로젝트의 `firmware/` 를 한 글자도 고치지 않고 실제 마이크로컨트롤러에서 돌린다.**
A5에서 가짜 레지스터로 한 것을 진짜 레지스터로 한다.

보드 없이 시작하는 방법:

- **QEMU** 또는 **Renode**: PC에서 ARM Cortex-M 칩을 흉내 내는 에뮬레이터 (무료). 컴파일러는 `arm-none-eabi-gcc`. 보드를 사기 전에 "운영체제 없는 프로그램이 어떻게 시작되는지"를 볼 수 있다.

보드로 하는 방법:

- **STM32 Nucleo** 계열 (2~3만 원대, 디버거가 보드에 붙어 있다). 자료가 가장 많다. 구체적인 모델은 살 때 재고와 자료를 보고 고른다.
- 여기에 엔코더 달린 작은 DC 모터와 모터 드라이버 모듈을 붙이면 이 프로젝트의 실물판이 된다. (계획서의 "범위 밖"이었던 것을 다음 프로젝트로.)

이 단계에서 새로 만나는 것:

| 주제 | 무엇인가 | 이 폴더와의 연결 |
|---|---|---|
| 시작 코드 (startup) | `main` 이전에 data 를 복사하고 bss 를 0으로 채우는 코드 | A1 Q2 |
| 링커 스크립트 | 플래시와 RAM의 주소, 각 구역을 어디에 놓을지 적은 파일 | A1의 메모리 지도 |
| 벡터 테이블 | 인터럽트 번호 → 처리 함수 주소의 표 (함수 포인터 배열) | c_notes 6절, A6 |
| 클록 설정, 타이머, PWM, ADC | 레지스터 설정 | A5 |
| 디버거 (gdb, 중단점, 메모리 보기) | 실행을 멈추고 변수와 레지스터를 본다 | 전부 |

추천 자료:

- **Miro Samek, "Modern Embedded Systems Programming"** (유튜브 무료 강의). 레지스터, 스택, 인터럽트, 시작 코드, RTOS 를 처음부터 직접 만들어 가며 설명한다. 이 폴더와 방향이 같다.
- **Making Embedded Systems** (Elecia White). 펌웨어 설계 전반 (구조, 인터럽트, 메모리, 전력). 코드보다 사고방식을 다룬다.
- 칩 제조사의 **레퍼런스 매뉴얼**. 처음에는 읽기 힘들지만, 타이머 장 하나를 끝까지 읽어 보는 경험이 중요하다.

## 3단계. 여러 작업을 다룬다 (RTOS와 운영체제)

M8의 P8, A6에서 "지금 아는 것으로는 풀 수 없다"고 남긴 것을 푸는 단계다.

| 주제 | 풀리는 문제 |
|---|---|
| 작업(task)과 스케줄링, 우선순위 | 제어 루프가 통신·표시보다 먼저 실행되게 한다 (P8) |
| 문맥 전환 (context switch) | 작업마다 스택이 따로 있다. 전환할 때 CPU 레지스터를 스택에 저장한다 (A3) |
| 큐, 세마포어, 뮤텍스 | 작업 사이에 데이터를 안전하게 넘긴다 (A6) |
| 우선순위 역전, 교착 상태 | 자물쇠를 잘못 쓰면 생기는 문제 |
| 마감 시간 분석 | "모든 작업이 주기를 지킨다"를 계산으로 보인다 (M8 타이밍의 확장) |

자료:

- **FreeRTOS** 공식 문서와 입문서 (무료). 가장 널리 쓰이는 작은 RTOS. 2단계의 보드에서 "제어 작업 + 통신 작업" 두 개를 돌려 본다.
- **Operating Systems: Three Easy Pieces** (OSTEP, 온라인 무료, 번역서 있음). 운영체제 교과서. 가상화(프로세스, 메모리) → 동시성 → 저장 장치 순서. 동시성 부분이 A6의 다음 내용이다.
- **MIT 6.S081 (xv6)** 강의와 실습 (무료 공개). 작은 운영체제의 소스 전체를 읽고 고친다. 어렵지만, 여기까지 가면 "시스템 소프트웨어를 한다"고 말할 수 있다.

## 4단계. 도구를 손에 익힌다

어느 단계에서든 함께 는다.

- **gdb**: 중단점, 한 줄씩 실행, 메모리 들여다보기 (`x/16xb &변수`). A2의 `dump` 를 디버거로 하는 것.
- **Makefile**: `run.py` 가 하는 일을 표준 도구로.
- **맵 파일** (`gcc -Wl,-Map=out.map`): 모든 변수와 함수가 어느 주소에 놓였는지의 목록. A1의 지도를 실제 프로그램 전체에 대해 본다.
- **sanitizer**: `-fsanitize=address`, `-fsanitize=thread`, `-fsanitize=undefined`.
- **git**: 브랜치, PR, 되돌리기. 이 프로젝트에서 이미 쓰고 있다.

## 대학 과목과의 대응

컴퓨터소프트웨어 전공의 일반적인 과목 이름으로 적는다. 실제 과목명과 학년은 **진학할 학교의 교과과정표에서 확인한다.**

| 이 폴더 | 이어지는 과목 |
|---|---|
| A1, A3, A4 (메모리 지도, 스택, 힙) | 시스템프로그래밍, 운영체제 (메모리 관리) |
| A2 (바이트 표현) | 컴퓨터구조 |
| A5 (레지스터) | 컴퓨터구조, 임베디드시스템 / 마이크로프로세서 |
| A6 (경쟁 상태) | 운영체제 (동시성, 동기화) |
| M8 (타이밍) | 컴퓨터구조 (성능), 실시간 시스템 |
| M5, M9 (제어) | 제어공학 (전자공학 쪽) |
| M7 (필터) | 신호및시스템, 디지털신호처리 (전자공학 쪽) |

전자공학과 소프트웨어 양쪽에 걸쳐 있다는 것이 펌웨어라는 분야의 성격이다.

## 학업계획서와의 연결

쓸 수 있는 흐름 (실제로 한 것만 쓴다):

1. 프로젝트에서 **이런 버그들이 "값이 어디에, 얼마나 오래 사는가"에서 나온다**는 것을 보았다. (학습 기록의 구체적인 예 하나)
2. 그래서 메모리를 따로 파고들었다. 주소를 찍어 보고, 일부러 망가뜨려 보았다. (A1~A6 중 실제로 한 것, 예상이 틀렸던 것)
3. 그 과정에서 **지금의 지식으로 닿지 않는 곳**을 알았다: 동적 메모리 관리, 여러 작업의 스케줄링과 동기화. (A4, A6에서 실제로 막힌 것)
4. 그것을 배우는 곳이 시스템프로그래밍과 운영체제다.

"포인터를 공부했다"보다 "어떤 버그를 메모리 관점에서 설명할 수 있게 되었고, 어디서 한계를 만났다"가 훨씬 구체적이다.

어느 것이든 이 프로젝트와 같은 방식으로 한다: 사양을 먼저 적고, 문제가 드러나게 실험하고, 기록한다.
