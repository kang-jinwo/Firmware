# 심화: 메모리 모델과 펌웨어

프로젝트(M0~M10)는 전자공학 2학년까지 배운 것을 하나로 잇는 것이 목적이었다.
이 폴더는 그중 **하나를 깊이 판다**: 프로그램이 메모리를 어떻게 쓰는가, 그리고 그것이 펌웨어에서 왜 중요한가.

프로젝트를 빠르게 훑은 뒤 여기를 제대로 한다. M4(펌웨어 구조)까지만 봐도 A1~A4는 시작할 수 있다.

## 두 가지 길

| 길 | 문서 | 시간 | 방식 |
|---|---|---|---|
| **개요 (권장 시작점)** | [`OVERVIEW.md`](OVERVIEW.md) | 1~2시간 | 그림과 흐름. 실습은 실행만 하고 출력의 한 줄만 본다. 코드를 쓰지 않는다 |
| 깊이 | A1 ~ A6 | 장마다 반나절~하루 | 예상 → 실행 → 설명 → 질문 → 직접 코드 쓰기 (선택) |

개요만 읽어도 메모리 구조의 흐름과 그것이 설계에 주는 영향은 잡힌다. 깊이는 관심 가는 장만 고른다.

## 세 가지 질문

모든 장이 이 세 질문으로 돌아온다.

1. 이 값은 **어디에** 사는가? (코드, data/bss, 스택, 힙, 레지스터)
2. **얼마나 오래** 사는가?
3. **누가** 바꿀 수 있는가?

## 실습 방법

```
python run.py lab a1_memory_map
```

각 장은 같은 순서로 되어 있다.

1. **먼저 예상한다** — 실행하기 전에 종이에 답을 적는다. 이 단계를 건너뛰면 남는 것이 절반으로 준다.
2. **실행한다** — 예상과 다른 줄에 표시한다.
3. **설명을 읽는다**
4. **질문** — 접힌 답을 펴기 전에 생각한다.
5. **직접 해 볼 것** — 코드를 고치거나 새로 쓴다. 여기서 쓴 코드는 `advanced/my/` 폴더를 만들어 모아 둔다.

주소 값은 실행할 때마다, 컴퓨터마다 다르다. 볼 것은 숫자 자체가 아니라 **어느 것끼리 가깝고 어느 것끼리 먼가**다.

막힌 것, 예상이 틀렸던 것은 `log/QNA.md` 와 학습 기록에 남긴다. 예상이 틀린 기록이 가장 좋은 재료다.
