# M5. 펌웨어 2판: PI 제어, 그리고 P1 실험

**목표**: 적분을 더해 남는 오차를 없앤다. 이득을 올리면 왜 출렁이는지 고유값으로 설명한다.
**끝났다는 기준**: 오차가 없어진다. P1 실험을 하고 학습 기록을 쓴다.

## 1. 읽을 파일

1. `firmware/controller.c` 의 `control_pi`
2. `firmware/controller.h` 의 `struct Controller` — 제어기가 기억하는 것들

## 2. 설명

### 적분: 오차를 쌓아 둔다

P 제어의 문제는 "오차가 0이면 듀티도 0"이었다. 그래서 **오차가 0이어도 듀티를 유지해 줄 무언가**가 필요하다.

적분 항은 오차를 매 주기 조금씩 쌓는다.

```
적분 += ki × 오차 × dt
듀티  = kp × 오차 + 적분
```

- 오차가 양수(느리다)인 동안 적분이 계속 커진다 → 듀티가 계속 커진다.
- 오차가 0이 되면 적분은 **더 커지지도 줄지도 않고 그 값에 머문다.**
- 그래서 자리를 잡은 뒤에는 오차 = 0, 적분 = 0.337 (필요한 듀티 그 자체)이 된다.

적분은 "지금까지의 오차를 기억하는 변수"다. 그래서 `Controller` 구조체 안에 `integ` 가 있고, 함수가 끝나도 값이 남도록 포인터로 넘긴다.

```c
int control_pi(Controller *c, int target, int measured)
{
    float e = (float)(target - measured);
    float add = c->ki * e * c->dt;      // 이번 주기에 쌓을 양
    float u;

    c->integ += add;                    // c가 가리키는 구조체 안의 값을 고친다 → 다음 주기에도 남는다
    u = c->kp * e + c->integ;
    ...
```

`× dt` 를 곱하는 이유: 적분은 "오차 × 시간"의 넓이다. 1 ms마다 폭 dt짜리 직사각형을 하나씩 더하는 것이다 (구분구적법). dt를 곱해 두면 제어 주기를 바꿔도 ki의 뜻이 변하지 않는다.

### 이득은 어떻게 정했나

모터를 "시정수 τm = 0.099 s, 듀티 1당 1188 rad/s"인 1차 시스템으로 본다 (M2의 지배 극점).

kp = 0.002: 시작할 때 듀티가 0.002 × 400 = 0.8 로 포화되지 않는 값.
ki = kp / τm ≈ 0.02: 이렇게 고르면 닫힌 루프의 시정수가

```
τ = τm / (1188 × kp) = 0.099 / 2.376 = 41.7 ms
```

가 되고, 출렁임 없이 올라간다 (아래 3절에서 식으로 확인한다).
±2 % 안에 들어가는 시간은 약 3.9 × τ = 0.163 s 로 예상된다. (e^(−3.9) ≈ 0.02)

## 3. 안정성을 행렬로 보기 (3단계: 선형대수)

### 손으로 먼저: 2차식의 판별식

모터를 1차로 단순화하고 PI를 붙이면 변수가 둘(속도 ω, 적분 z)이다. 정리하면 특성방정식이 나온다.

```
τm · s² + (1 + 1188·kp) · s + 1188·ki = 0
```

회로이론의 R-L-C 2차 응답과 같은 모양이다. 근이 실수면 출렁이지 않고, 복소수면 출렁인다. 판별식으로 가른다.

```
(1 + 1188·kp)² − 4 · τm · 1188 · ki   ≥ 0  이면 출렁이지 않는다
```

kp = 0.002 를 넣으면: 11.40 − 470.4 × ki ≥ 0 → **ki ≤ 0.0242**.
기준 이득 ki = 0.02 는 이 경계 바로 안쪽이다. 출렁이지 않으면서 가장 빠른 근처를 고른 것이다.

### 행렬로: x' = A x

단순화하지 않고 전류까지 넣으면 상태가 셋이다: x = [i, ω, z].

```
v  = Vs · ( kp·(목표 − ω) + z )          ← 제어기가 만드는 전압
i' = ( v − R·i − Ke·ω ) / L
ω' = ( Kt·i − b·ω ) / J
z' = ki · (목표 − ω)
```

**직접 해 볼 것**: v를 첫 식에 넣고, 세 식을 i, ω, z 의 계수별로 정리해 3×3 행렬 A를 구한다. (목표가 들어간 항은 상수라서 안정성과 상관없다. 빼놓는다.)

<details><summary>▶ 답과 설명 보기</summary>

```
        i 의 계수      ω 의 계수            z 의 계수
i' = [  −R/L       −(Ke + Vs·kp)/L        Vs/L   ]
ω' = [   Kt/J          −b/J                0     ]
z' = [    0             −ki                 0     ]
```

숫자를 넣으면 (kp = 0.002, ki = 0.02)

```
A = [ −2000    −68     24000 ]
    [  1000    −0.1      0   ]
    [    0     −0.02     0   ]
```

A의 고유값 λ 하나하나가 e^(λt) 모양의 움직임 하나에 대응한다.

- λ의 실수부가 음수 → 그 움직임은 사라진다 (안정). 0에서 멀수록 빨리 사라진다.
- 실수부가 양수 → 커진다 (불안정).
- 허수부가 있다 → 출렁인다. 허수부가 각주파수 [rad/s].

이것은 선형대수의 "대각화하면 연립 미분방정식이 각각 따로 풀린다"는 내용 그대로다.
</details>

## 5. 생각해 볼 질문

**Q1.** 자리를 잡은 뒤 적분 항 `integ` 의 값은 얼마일까? 왜 그 값인가?

<details><summary>▶ 답과 설명 보기</summary>

약 **0.337**. 400 rad/s를 유지하는 데 필요한 듀티 그 자체다.

자리를 잡으면 오차가 0이므로 kp × 오차 = 0 이고, 듀티 전부를 적분 항이 맡는다. 적분은 "오차가 0이 될 때까지 계속 움직이다가, 오차가 0이 되는 듀티를 찾으면 거기서 멈추는" 장치다. 필요한 듀티가 얼마인지 제어기가 미리 알 필요가 없다. 마찰이 바뀌거나 전원 전압이 떨어져도 적분이 알아서 새 값을 찾아간다. 이것이 PI 제어가 널리 쓰이는 이유다.
</details>

**Q2.** ki = 0.2 일 때 예측 주파수는 7.4 Hz, 그래프에서 읽은 값은 7.2 Hz다. 잘 맞는다. 그런데 ki = 2 는 예측이 "천천히 가라앉는다"인데 실제로는 가라앉지 않는다. 왜 다를까?

<details><summary>▶ 답과 설명 보기</summary>

행렬 A는 **연속 시간, 선형** 모델이다. 실제 시뮬레이션에는 A에 들어 있지 않은 것이 세 가지 있다.

1. **포화**: 듀티가 0~1로 잘린다. ki = 2 에서는 듀티가 0과 1에 계속 부딪힌다. 잘리는 순간 식이 달라지므로 A가 더 이상 맞지 않는다.
2. **1 ms 샘플링**: 펌웨어는 1 ms에 한 번만 보고, 그 사이 듀티는 고정이다. 평균적으로 0.5 ms쯤 늦게 반응하는 셈이다. 24.7 Hz(주기 40 ms)의 출렁임에는 작은 지연이지만, 가라앉는 힘이 원래 약했기 때문에(실수부 −11) 조금만 나빠져도 눈에 띈다.
3. **센서 반올림**: 1 rad/s 단위.

교훈: **고유값은 "어느 쪽으로 가는지"를 잘 알려 주지만, 한계 근처에서는 모델에 넣지 않은 것들이 결과를 정한다.** 안정 한계에 딱 맞춰 설계하지 않고 여유를 두는 이유다.
</details>

**Q3.** kp = 0.3 일 때 속도는 멀쩡해 보인다. 그러면 괜찮은 것 아닌가?

<details><summary>▶ 답과 설명 보기</summary>

속도만 보면 6 rad/s(1.5 %)의 떨림이라 검증 기준도 통과할 수 있다. 하지만 듀티와 전류를 보면 다르다.

- 센서가 1 rad/s 바뀔 때마다 듀티가 0.3씩 뛴다. 속도가 목표를 1~2 rad/s 넘으면 듀티 0, 모자라면 1.
- 전류가 −3.9 A ~ +6.9 A를 오간다. 기준 이득에서는 0.1 A였다. 저항 열은 전류의 제곱에 비례하므로 수백 배다. 실제 모터라면 뜨거워지고, 소리가 나고, 기어가 닳는다.

속도가 조용한 것은 회전 관성 J가 저역통과 필터 역할을 해서 전류의 요동을 가려 주기 때문이다.

교훈: **출력(속도) 하나만 보고 "된다"고 하면 안 된다.** 검증 기준에 듀티 범위(V5)가 들어 있는 이유이고, M6에서 무엇을 재야 할지 정할 때 기억할 점이다.
</details>

**Q4.** `control_pi` 에서 `c->integ += add;` 대신 지역 변수 `float integ = 0; integ += add;` 로 쓰면 어떻게 되는가?

<details><summary>▶ 답과 설명 보기</summary>

지역 변수는 함수가 불릴 때마다 새로 만들어지고 끝나면 사라진다. 매 주기 `integ` 가 0에서 시작하므로 적분이 쌓이지 않는다. 결과는 P 제어와 거의 같아지고 (kp × e + ki × e × dt, 뒤 항은 아주 작다) 오차 29.6 %가 다시 남는다.

"주기를 넘어서 기억해야 하는 값"은 함수 밖(구조체, static 변수)에 있어야 한다. 이것을 **상태**라고 한다. 펌웨어의 버그 중 많은 수가 "상태를 어디에 두고, 누가 언제 고치는가"에서 나온다.

M8의 P5에서 똑같은 증상(오차 29.6 %)이 전혀 다른 원인으로 다시 나온다. 기억해 둔다.
</details>
