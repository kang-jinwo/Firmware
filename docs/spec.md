# M1. 사양서

**목표**: 무엇을 만들고, 무엇이 되면 "됐다"고 할지 코드를 보기 전에 정한다.
**끝났다는 기준**: 3절의 손 계산을 직접 하고 값이 맞는다.

## 1. 모터는 어떻게 도는가 (1단계: 전자장)

자기장 B 안에 놓인 길이 L의 도선에 전류 I가 흐르면 힘 F = I L × B 를 받는다.
도선이 회전축에서 r만큼 떨어져 있으면 토크는 힘 × 팔 길이다. 코일을 N번 감으면 N배가 된다.

- 토크 = (N · B · L · r · 2) · I = **Kt · I**
  → 토크 상수 Kt는 "전류 1 A가 만드는 토크"이고, 모터의 구조(감은 수, 자석 세기, 크기)로 정해진다.

코일이 돌면 도선이 자기장을 가로지르므로 전압이 유도된다 (패러데이 법칙). 속도가 빠를수록 크다.

- 역기전력 e = (N · B · L · r · 2) · ω = **Ke · ω**
  → 역기전력 상수 Ke는 "1 rad/s로 돌 때 생기는 전압"이다. 걸어 준 전압을 깎는 방향이다.

괄호 안이 같다. 그래서 SI 단위로 쓰면 Kt 와 Ke 는 같은 숫자다 (이 프로젝트에서는 둘 다 0.01).

## 2. 식과 값

```
전기:  L · di/dt = v − R·i − Ke·ω        (KVL: 걸어 준 전압 = 저항 전압 + 인덕터 전압 + 역기전력)
기계:  J · dω/dt = Kt·i − b·ω            (뉴턴: 관성 × 각가속도 = 모터 토크 − 마찰 토크)
```

| 기호 | 뜻 | 값 |
|---|---|---|
| Vs | 전원 전압 | 12 V |
| R | 권선 저항 | 1 Ω |
| L | 권선 인덕턴스 | 0.5 mH |
| Kt, Ke | 토크 상수, 역기전력 상수 | 0.01 (N·m/A, V·s/rad) |
| J | 회전 관성 | 1e-5 kg·m² |
| b | 마찰 계수 | 1e-6 N·m·s/rad |
| PWM 주파수 | | 20 kHz (주기 50 µs) |
| 제어 주기 | 펌웨어 루프가 도는 간격 | 1 ms |
| 시뮬레이션 간격 | 모터 식을 푸는 간격 | 1 µs |
| 센서 | 속도를 정수 [rad/s] 로 준다 | 분해능 1 rad/s |
| 듀티 | 정수 0 ~ 1000 (1000 = 100 %) | 분해능 0.1 % |

## 3. 손 계산 (직접 한다)

종이에 먼저 계산하고 답을 펼친다. M2에서 시뮬레이션 결과와 비교할 값들이다.

**계산 1.** 전기 시정수: 모터를 붙잡아 못 돌게 하고(ω = 0) 전압을 걸면 전류는 R-L 회로처럼 오른다. 시정수는?

<details><summary>▶ 답과 설명 보기</summary>

ω = 0 이면 전기 식은 L · di/dt = v − R·i, 즉 회로이론의 R-L 직렬 회로다.

τe = L / R = 0.5 mH / 1 Ω = **0.5 ms**

전압을 건 뒤 0.5 ms 만에 전류가 최종값의 63 %까지 오른다. 최종값(못 돌게 했을 때)은 Vs/R = 12 A 다. 이 값을 **기동 전류**라고 하며, 모터가 처음 돌기 시작할 때 큰 전류가 흐르는 이유다.
</details>

**계산 2.** 12 V를 계속 걸어 두면 최종 속도는? (힌트: 다 올라가면 di/dt = 0, dω/dt = 0)

<details><summary>▶ 답과 설명 보기</summary>

변화가 멈춘 상태에서는 두 식의 왼쪽이 0이다.

- 기계 식: 0 = Kt·i − b·ω → i = b·ω / Kt
- 전기 식: 0 = v − R·i − Ke·ω → v = R·(b·ω/Kt) + Ke·ω

ω = v / (Ke + R·b/Kt) = 12 / (0.01 + 1×1e-6/0.01) = 12 / 0.0101 = **1188.1 rad/s**

마찰이 없다면(b = 0) ω = Vs/Ke = 1200 rad/s 다. 이것은 "역기전력이 전원 전압과 같아져서 전류가 0이 되는 속도"라는 뜻이다. 실제로는 마찰을 이길 만큼의 전류(약 0.12 A)가 필요해서 1 % 낮다.

앞으로 자주 쓸 숫자: **듀티 1당 속도 1188 rad/s**. 듀티 d를 주면 최종 속도는 약 1188 × d 다.
</details>

**계산 3.** 기계 시정수: 속도가 최종값의 63 %에 닿는 시간은 대략 얼마인가? (힌트: 전류는 속도보다 훨씬 빨리 변하므로, 전기 식에서 L·di/dt ≈ 0 으로 두고 i를 구해 기계 식에 넣는다)

<details><summary>▶ 답과 설명 보기</summary>

전기 쪽이 훨씬 빠르므로(0.5 ms) 속도가 변하는 동안 전류는 항상 "그 순간의 균형값"에 있다고 본다.

- 전기 식에서 L·di/dt ≈ 0 → i ≈ (v − Ke·ω) / R
- 기계 식에 넣으면: J · dω/dt = Kt·(v − Ke·ω)/R − b·ω

정리하면 J · dω/dt = −(Kt·Ke/R + b)·ω + (Kt/R)·v. 이것은 1차 미분방정식(R-C 회로와 같은 모양)이고 시정수는

τm = J / (Kt·Ke/R + b) = J·R / (Kt·Ke + R·b) = 1e-5 / (1e-4 + 1e-6) = **0.099 s ≈ 0.1 s**

전기 시정수(0.5 ms)의 약 200배다. "빠른 것 하나, 느린 것 하나"로 나뉜다는 점이 이 모터의 핵심이고, 덕분에 느린 쪽만 보고 제어기를 설계할 수 있다.
</details>

**계산 4 (추가).** 속도 400 rad/s로 계속 돌리려면 듀티는 얼마가 필요한가?

<details><summary>▶ 답과 설명 보기</summary>

평균 전압이 Vs × d 이고, 최종 속도 = 평균 전압 / 0.0101 이므로

d = 400 × 0.0101 / 12 = **0.337**

M5에서 PI 제어가 자리를 잡았을 때 듀티가 이 값(0.336~0.338)에 머무는지 확인한다.
</details>

## 4. 검증 기준

**코드를 보기 전에 정한다.** 결과를 보고 나서 기준을 정하면, 나온 결과에 기준을 맞추게 된다.

기준 실험: 목표 속도 400 rad/s, 정지 상태에서 시작, 1초 동안.

| 번호 | 항목 | 기준 | 이렇게 정한 이유 |
|---|---|---|---|
| V1 | 목표 속도 도달 시간 | 목표의 ±2 % 안에 들어가 다시 나오지 않는 시각 ≤ 0.25 s | 12 V를 다 걸어도 400 rad/s까지 0.04 s가 걸린다 (아래 계산). 그 6배까지 허용 |
| V2 | 오버슈트 | 목표의 10 % 이하 | 계획서의 예시 값 |
| V3 | 정상 상태 오차 | 마지막 0.2 s 평균이 목표의 1 % 이내 | 센서 분해능이 1 rad/s (0.25 %) 이므로 그보다 넉넉하게 |
| V4 | 잡음이 있을 때 속도 흔들림 | 센서 잡음 표준편차 20 rad/s, 이동평균 8개일 때, 마지막 0.5 s 동안 실제 속도의 (최대 − 최소) ≤ 20 rad/s | 센서 값은 ±60 rad/s(±3σ)로 흔들린다. 실제 속도는 목표의 5 % 폭 안에 있어야 한다 |
| V5 | 듀티 범위 | 펌웨어가 요청한 듀티가 항상 0 ~ 1 | 범위 밖의 값은 실제 타이머 레지스터에서 엉뚱한 동작을 만든다 |
| V6 | 루프 실행 시간 추정값 | 제어 주기(1 ms)보다 짧다 | 주기 안에 계산이 끝나야 한다 |

V1의 "0.04 s" 계산: 12 V를 걸면 ω(t) = 1188 × (1 − e^(−t/0.099)). 400에 닿는 시각은
t = −0.099 × ln(1 − 400/1188) = 0.041 s. 이보다 빠를 수는 없다 (물리적 한계).

## 5. 생각해 볼 질문

**Q1.** Kt 와 Ke 의 숫자가 같은 것은 우연일까?

<details><summary>▶ 답과 설명 보기</summary>

우연이 아니다. 에너지 보존 때문이다.

- 전기에서 기계로 넘어가는 전력 = 역기전력 × 전류 = Ke·ω·i
- 기계가 받는 전력 = 토크 × 각속도 = Kt·i·ω

둘이 같아야 하므로 Ke = Kt. (저항에서 열로 나가는 R·i² 는 따로 계산된다.)
다르다면 에너지가 어디선가 생기거나 사라지는 모터가 된다.
</details>

**Q2.** 검증 기준을 왜 코드보다 먼저 적는가?

<details><summary>▶ 답과 설명 보기</summary>

나중에 정하면 "지금 나온 결과가 통과하도록" 기준을 고르게 된다. 그러면 테스트는 항상 PASS이고 아무것도 검증하지 않는다.

기준을 먼저 적으면 테스트가 **사양**을 검사한다. 코드가 바뀌어도 기준은 그대로이므로, 코드가 나빠지면 FAIL이 난다. 회사에서 사양서(요구사항)와 검증 계획을 구현보다 먼저 쓰는 이유도 같다.
</details>
