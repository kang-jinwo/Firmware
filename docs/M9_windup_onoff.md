## 2. 적분이 계속 쌓인다 (P6)

### 실험

목표를 1500 rad/s 로 준다. 이 모터의 최고 속도는 1188 rad/s 라서 **절대 닿을 수 없다.** 1초 뒤에 목표를 400으로 낮춘다.

```
python run.py P6
```

| 항목 | anti-windup 없음 | 있음 |
|---|---|---|
| 0 ~ 1 s | 듀티 1.0, 속도 1188 | 같다 |
| 목표를 낮춘 뒤 듀티가 1.0 에서 내려오기 시작하는 시각 | **1.38 s** (0.38 s 동안 전속력 유지) | 1.00 s (즉시) |
| 속도가 400 의 ±2 % 안에 들어오는 시각 | 1.90 s | 1.13 s |

참고 그래프: `solution/figures/p6_windup.png`

"속도를 줄여라"는 명령을 받고도 0.38초 동안 전속력으로 돈다. 사람이 다칠 수 있는 종류의 버그다.

### 왜 그런가

0 ~ 1 s 동안 오차는 1500 − 1188 = 312 로 일정하다. 적분은 매 주기 계속 쌓인다.

```
적분 = ki × 오차 × 시간 = 0.02 × 312 × 1 s = 6.24
```

듀티는 1.0 까지만 쓸 수 있는데 적분은 6.24 다. 5.24 는 아무 일도 하지 못하고 쌓여만 있던 "빚"이다.

목표를 400으로 낮추면 오차가 −788 이 된다. 듀티 = kp × (−788) + 적분 = −1.58 + 6.24 = 4.66 → 여전히 1.0 으로 잘린다. 적분이 초당 0.02 × 788 = 15.8 씩 줄어, 듀티가 1 아래로 내려올 때까지 약 0.23 s 가 걸리고, 그동안에도 속도가 떨어지며 오차가 변하므로 실제로는 0.38 s 가 걸린다.

### 고친 방법: 포화 중에는 적분을 멈춘다

```c
if (c->anti_windup) {
    // 듀티가 이미 한계인데 적분이 그 방향으로 더 쌓이려 하면, 방금 더한 것을 되돌린다
    if ((u > 1.0f && add > 0.0f) || (u < 0.0f && add < 0.0f)) {
        c->integ -= add;
        u = c->kp * e + c->integ;
    }
}
```

"어차피 더 밀 수 없으면 더 쌓지 않는다."

**Q3.** anti-windup 을 켠 결과에서 속도가 400 아래(383)까지 잠깐 내려갔다가 올라온다. 왜 그럴까? 완벽한 해결인가?

<details><summary>▶ 답과 설명 보기</summary>

포화 중에 적분이 1.0 근처(쓸 수 있는 최대)에 머물러 있었다. 목표를 낮추면 듀티가 0으로 떨어지고, 이번에는 **아래쪽 한계(0)** 에 걸린다. 속도가 내려오는 동안 적분은 0.337(400을 유지하는 값)보다 낮은 곳까지 내려갔다가 다시 올라와야 한다. 그 차이가 4 %의 언더슈트로 나타난다.

완벽하지 않다. 더 나은 방법들이 있다 (잘린 양만큼 적분을 되돌리는 방식, 적분 값 자체에 한계를 두는 방식). 어느 것이 좋은지는 상황에 따라 다르고, 정하는 기준은 제어공학에서 배운다.

계획서에서 P6을 "완전히 해결하지 않아도 된다"고 한 부분이다. 여기까지가 지금 아는 것으로 한 것이고, 학습 기록에는 **실제로 어디까지 이해했는지**를 적는다.
</details>

## 3. 켜고 끄기 제어와 히스테리시스 (P7)

### 설명

PWM 없이 가장 단순하게: 느리면 켜고, 빠르면 끈다.

```
측정값 < 목표 → 듀티 1
측정값 > 목표 → 듀티 0
```

전기 히터, 냉장고가 이렇게 동작한다. 문제는 목표 근처에서 생긴다. 잡음 때문에 측정값이 목표 위아래로 오가면 스위치가 매 주기 뒤집힌다 (채터링).

히스테리시스는 켜는 기준과 끄는 기준을 다르게 둔다.

```
측정값 < 목표 − h  → 켠다
측정값 > 목표 + h  → 끈다
그 사이            → 이전 상태 그대로
```

```
        끈다 ◀─────────────┐
                           │
  상태                     │
   켬 ━━━━━━━━━━━━━━━━━━━━┓
                  ┃        ┃
   끔 ━━━━━━━━━━━━┛━━━━━━━━━━━━
              목표−h      목표+h     측정값
                  │
                  └─────────────▶ 켠다
```

회로이론/전자회로의 **슈미트 트리거**와 같은 원리다. 비교기에 양의 되먹임을 걸어 문턱값을 두 개로 만드는 것. 그것을 코드로 쓰면 변수 하나(`c->on`, 이전 상태)와 `if` 두 개가 된다.

"그 사이에서는 이전 상태 그대로"가 가능하려면 이전 상태를 **기억**해야 한다. 그래서 `on` 이 `Controller` 구조체 안에 있다.


### 생각해 볼 질문

**Q1.** 히스테리시스를 넓히면 스위칭 횟수는 줄지만 속도 흔들림은 커진다. 왜 둘을 동시에 줄일 수 없는가?

<details><summary>▶ 답과 설명 보기</summary>

켜고 끄기 제어는 속도가 띠의 한쪽 끝에 닿아야만 방향을 바꾼다. 띠가 넓으면 한쪽 끝에서 반대쪽 끝까지 가는 데 오래 걸리므로 덜 자주 바뀌고, 대신 속도는 그 넓은 띠 전체를 오간다.

- h = 20 → 띠 폭 40 → 속도 흔들림 59 (띠 폭 + 1 ms 사이에 더 지나친 양 + 잡음)
- h = 0 → 띠 폭 0 → 그래도 흔들림 30. 1 ms 에 한 번만 보기 때문에, 그 사이 전압 12 V 또는 0 V 로 지나치게 간다.

스위칭 횟수와 정밀도를 맞바꾸는 관계다. 스위치(릴레이, 트랜지스터)는 켜고 끌 때마다 닳거나 열이 나므로 횟수를 줄이고 싶고, 제어는 정밀하게 하고 싶다. h는 그 사이에서 고르는 값이다.
</details>

**Q2.** 켜고 끄기 제어의 전류는 −4 ~ 8 A 다. PI + PWM 은 0.1 A 였다. PWM도 결국 켜고 끄는 것인데 왜 이렇게 다른가?

<details><summary>▶ 답과 설명 보기</summary>

**켜고 끄는 빠르기**가 다르다.

- PWM: 50 µs 마다. 전기 시정수 0.5 ms 의 1/10. 전류가 변하기 전에 전압이 뒤집히므로 인덕터가 평균을 낸다 (M3). 리플 0.3 A.
- 켜고 끄기 제어: 빨라야 1 ms 마다. 전기 시정수의 2배. 전류가 12 V 또는 0 V 에 대한 최종값을 향해 끝까지 간다.

M3의 Q1(PWM 주파수를 200 Hz 로 낮추면)과 같은 현상이다. 켜고 끄기 제어는 "제어 주기에 묶인 아주 느린 PWM"인 셈이다.

히터나 냉장고에서 켜고 끄기 제어가 잘 통하는 것은 온도의 시정수가 몇 분 단위로 아주 길기 때문이다. 대상이 느리면 단순한 제어로 충분하다. **제어 방식은 대상의 빠르기를 보고 고른다.**
</details>

**Q3.** `fw_init` 은 `switch` 로 제어 함수를 골라 `ctrl.step` 에 넣고, `fw_tick` 은 `ctrl.step(...)` 을 부른다. `fw_tick` 안에서 매번 `if (mode == P) ... else if (mode == PI) ...` 로 고르는 것과 비교해 어떤 점이 다른가?

<details><summary>▶ 답과 설명 보기</summary>

결과는 같다. 다른 점:

- **고르는 일을 한 번만 한다.** 매 주기 `if` 를 여러 번 거치지 않는다 (명령어 수가 준다. 작지만 M8의 관점).
- **`fw_tick` 이 제어 방식을 모른다.** 새 제어 방식을 추가할 때 `fw_tick` 은 고치지 않는다. 함수 하나를 만들고 `fw_init` 의 `switch` 에 한 줄을 넣으면 된다. 매 주기 도는 가장 중요한 함수를 건드리지 않아도 된다.
- **테스트가 쉽다.** `solution/test_controller.c` 는 함수 포인터 배열로 네 가지 제어 함수에 같은 검사를 한 번에 돌린다.

조건: 모든 제어 함수가 **같은 모양**(같은 인자, 같은 반환형)이어야 한다. `hal.h` 의 두 함수가 "세상과의 약속"이었다면, `ControlFn` 은 "제어 방식들 사이의 약속"이다. 약속(인터페이스)을 정해 두면 그 뒤의 것을 바꿔 끼울 수 있다는 점에서 같은 생각이다.

자세한 문법은 [`c_notes.md`](c_notes.md) 6절.
</details>
