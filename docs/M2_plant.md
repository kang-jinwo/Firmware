# M2. 모터 모델

**목표**: 모터 식을 C 코드로 풀고, 12 V를 걸었을 때의 응답이 손 계산과 맞는지 본다.
**끝났다는 기준**: 최종 속도와 시정수가 M1의 손 계산과 비슷하다.

## 1. 읽을 파일

1. `plant/motor.h` — 구조체 두 개와 함수 선언
2. `plant/motor.c` — 식을 푸는 곳 (40줄)
3. `sim/main.c` 의 맨 아래 `for` 문 — 시간을 전진시키는 곳

## 2. 설명

### 미분방정식을 컴퓨터로 푸는 법 (오일러 방법)

식은 "지금 상태에서 변화율이 얼마인가"를 알려 준다.

```
di/dt = (v − R·i − Ke·ω) / L
dω/dt = (Kt·i − b·ω) / J
```

아주 짧은 시간 dt 동안은 변화율이 거의 일정하다고 보면

```
새 값 = 지금 값 + 변화율 × dt
```

이것을 1 µs마다 되풀이한다. `motor_step` 이 하는 일은 이것이 전부다.

```c
double di_dt = (v - p->R * m->i - p->Ke * m->w) / p->L;
double dw_dt = (p->Kt * m->i - p->b * m->w) / p->J;
m->i += di_dt * dt;
m->w += dw_dt * dt;
```

### 구조체와 포인터

`MotorState` 는 전류와 속도를 한 묶음으로 담는다. `motor_step` 은 이 묶음을 **포인터**로 받는다.

```
main 쪽                       motor_step 쪽
┌──────────────┐
│ motor        │  ← 주소 0x1000 (예)
│   i = 0.0    │
│   w = 0.0    │               m = 0x1000   (motor가 있는 곳을 가리킨다)
└──────────────┘               m->i += ...  (0x1000에 있는 진짜 motor를 고친다)

호출: motor_step(&motor, ...)     & 는 "주소를 구한다"
```

`m->i` 는 `(*m).i` 를 줄여 쓴 것이다. "m이 가리키는 구조체의 i".

`const MotorParams *p` 의 `const` 는 "이 함수는 p가 가리키는 값을 읽기만 한다"는 약속이다. 모터 상수를 실수로 바꾸는 코드를 쓰면 컴파일러가 막아 준다.

### 2단계(회로이론)와의 연결: 전달함수

두 식을 라플라스 변환해서 정리하면 (초기값 0)

```
ω(s) / V(s) = Kt / ( (L·s + R)(J·s + b) + Kt·Ke )
```

분모가 s의 2차식이므로 극점이 두 개다. 계산하면 s = −1990 과 s = −10.2 이고,
시정수로 바꾸면 1/1990 = 0.50 ms, 1/10.2 = 98.5 ms 다. M1에서 손으로 구한 전기 시정수, 기계 시정수와 같다.
(이 두 숫자는 M5에서 "행렬의 고유값"으로 다시 나온다.)

## 4. 생각해 볼 질문

**Q1.** 전류는 왜 처음에 11.7 A까지 솟았다가 0.1 A 근처로 떨어지는가?

<details><summary>▶ 답과 설명 보기</summary>

전류를 정하는 것은 v − Ke·ω (걸어 준 전압에서 역기전력을 뺀 것)다.

- 처음: ω = 0 이라 역기전력이 없다. 12 V가 전부 R과 L에 걸려 전류가 0.5 ms 시정수로 12 A를 향해 오른다.
- 그 사이 모터가 돌기 시작해 역기전력이 생긴다. 전류는 12 A에 닿기 전(11.74 A)에 꺾인다.
- 속도가 오를수록 역기전력이 커져 전류가 줄어든다.
- 끝: 역기전력이 11.88 V가 되면 남는 0.12 V가 0.12 A를 흘리고, 이 전류가 만드는 토크가 마찰과 정확히 비긴다.

즉 역기전력은 모터에 원래 들어 있는 **음의 되먹임(feedback)** 이다. 빨라지면 스스로 전류를 줄인다. 제어기를 붙이기 전에도 모터가 일정한 속도에 머무는 이유다.
</details>

**Q2.** `motor_step(MotorState m, ...)` 처럼 포인터가 아니라 값으로 받게 바꾸면 무슨 일이 생길까?

<details><summary>▶ 답과 설명 보기</summary>

C는 함수를 부를 때 인자를 **복사**한다. 값으로 받으면 `m` 은 `motor` 의 복사본이고, 함수 안에서 복사본을 고친 뒤 함수가 끝나면 복사본은 사라진다. 원래 `motor` 는 영원히 i = 0, w = 0 이다. 컴파일 오류도 경고도 없이 "모터가 돌지 않는" 결과만 나온다.

주소를 넘기면 복사되는 것은 주소(숫자 하나)이고, 그 주소를 따라가서 진짜를 고친다.

직접 해 보면 가장 잘 기억된다: `motor.h`, `motor.c` 의 `MotorState *m` 을 `MotorState m` 으로, `m->` 를 `m.` 로, `main.c` 의 `&motor` 를 `motor` 로 바꿔 `python run.py M2` 를 돌려 본다. (해 본 뒤 되돌린다: `git checkout plant sim`)
</details>

**Q3.** 시뮬레이션 간격은 왜 1 µs처럼 작아야 할까? 1 ms로 하면?

<details><summary>▶ 답과 설명 보기</summary>

오일러 방법은 "dt 동안 변화율이 일정하다"고 가정한다. 전류는 0.5 ms 시정수로 변하므로, dt가 그보다 훨씬 작아야 이 가정이 맞는다.

dt = 1 ms 로 하면 한 걸음에 전류가 12 V / 0.5 mH × 1 ms = 24 A 만큼 뛴다 (실제 한계는 12 A). 다음 걸음에서는 너무 커진 전류 때문에 반대로 더 크게 뛴다. 값이 걸음마다 부호를 바꾸며 커져서 발산한다. 모터가 불안정한 것이 아니라 **계산 방법이 불안정**해진 것이다.

기준: dt가 가장 빠른 시정수의 2배보다 작아야 발산하지 않고, 정확하려면 1/10 이하가 좋다. 여기서는 PWM 한 주기(50 µs)도 잘게 나눠야 해서 1 µs를 쓴다.

이 생각은 M8의 P4(제어 주기를 늦추면 불안정해진다)와 똑같은 구조다. "빠르게 변하는 것을 느리게 들여다보면 틀린다."
</details>

**Q4.** 속도 그래프는 1차 시스템(R-C 충전 곡선)처럼 보인다. 식은 2개인데 왜 그럴까?

<details><summary>▶ 답과 설명 보기</summary>

극점이 −1990 과 −10.2 로 200배 차이가 나기 때문이다. 응답은 e^(−1990t) 항과 e^(−10.2t) 항의 합인데, 빠른 항은 2~3 ms 만에 사라지고 그 뒤로는 느린 항만 남는다.

그래프를 처음 5 ms만 확대하면 속도 곡선이 처음에 평평하게(기울기 0에서) 출발하는 것이 보인다. 그 부분이 2차 시스템의 흔적이다. 전류가 올라와야 토크가 생기기 때문이다.

"느린 극점이 응답을 지배한다"는 것을 **지배 극점**이라고 한다. M5에서 제어기를 설계할 때 모터를 "시정수 0.1 s짜리 1차 시스템"으로 단순하게 보는 근거다.
</details>

시정수는 J·R/(Kt·Ke + R·b) 로, 전압이 들어 있지 않다. 이 모터 식은 **선형**이라서 입력을 절반으로 줄이면 출력 전체가 모양은 그대로인 채 절반이 된다. 선형이라는 성질 덕분에 M3에서 "PWM의 평균만 보면 된다"는 말이 성립한다.
</details>
