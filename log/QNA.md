# 질문 기록

공부하면서 AI에게 한 질문과, 그것이 어떻게 풀렸는지를 모아 두는 파일.
M10에서 "어떤 어려움을 겪었고 어떻게 해결했는가"를 쓸 때의 재료다.

## 쓰는 규칙

- **AI가 적는다**: 내가 채팅에서 질문할 때마다 AI가 아래 표에 한 줄을 더하고, 아래쪽에 상세 항목을 추가한 뒤 GitHub에 올린다.
- **내가 적는다**: 상세 항목의 "내 말로 한 줄"은 비워 둔다. 이해한 뒤에 내가 직접 채운다. 여기가 채워져야 그 질문이 "해결"이다.
- 질문은 내가 한 말 그대로에 가깝게 적는다. 다듬지 않는다. 무엇을 몰랐는지가 그대로 남아야 한다.
- 상태: `해결` (내 말로 설명할 수 있다) / `부분` (답은 들었지만 아직 다 이해하지 못했다) / `남김` (지금 지식으로는 풀 수 없어 앞으로 배울 것으로 남긴다)

## 상세

### Q001. 내 컴퓨터가 꺼져 있어도 클라우드에서 GitHub에 파일을 만들 수 있는가
- 날짜: 2026-11-10
- 단계: M0
- 내가 한 질문: "지금은 컴퓨터 안 켜져 연결 안 돼 있잖아. 그러면 클라우드랑 연결되고 내가 지금 연결해놓은 깃허브랑 연결돼서 거기 안에서 파일 만들 수 있는 거지."
- 왜 막혔나: 작업이 어디서 실행되는지(내 컴퓨터인지 클라우드인지) 몰랐다.
- 답 요약: AI 세션은 클라우드의 임시 컴퓨터에서 돈다. 거기에 GitHub 저장소가 복제되어 있어서, 파일을 만들고 commit·push 하면 GitHub에 남는다. 임시 컴퓨터는 세션이 끝나면 사라지므로 push 한 것만 남는다. 내 컴퓨터에서는 `git pull` 로 받아 온다.
- 관련 파일: `docs/M0_setup.md`
- 내 말로 한 줄:

### Q002. GitHub에 올렸다는 파일이 왜 안 보이는가
- 날짜: 2026-11-11
- 단계: M0
- 내가 한 질문: "왜 안보이지 체크해"
- 왜 막혔나: git의 브랜치 개념을 몰랐다. GitHub 첫 화면은 `main` 브랜치만 보여 준다.
- 답 요약: 파일은 전부 작업 브랜치 `ccr-a795ff36-u6wtnd` 에 올라가 있고, `main` 에는 처음 만든 README 하나뿐이다. 브랜치는 같은 저장소 안의 "다른 버전의 폴더"와 같다. GitHub 화면 왼쪽 위의 브랜치 선택 버튼에서 작업 브랜치를 고르면 보인다. 작업 브랜치를 `main` 에 합치면(merge, 보통 PR로 한다) 첫 화면에서도 보인다.
- 관련 파일: Q001 에 이어서
- 내 말로 한 줄:

### Q003. 토큰을 아끼려면 공부를 여기서 할까, 정리한 것을 올릴까
- 날짜: 2026-11-11
- 단계: M1
- 내가 한 질문: "공부한것들 여기에 파편적으로 올릴까 아니면 여기서 공부할까 토큰 많이 쓸까봐 아끼고싶어서" (M1 정리 노트를 함께 올림)
- 왜 막혔나: 대화가 길어질수록 비용이 커지는 구조를 몰랐다.
- 답 요약: AI는 메시지를 받을 때마다 대화 전체를 다시 읽는다. 대화가 길수록 한 번 묻는 데 드는 양이 커진다. 그래서 (1) 공부는 문서로 혼자 하고, (2) 단계 하나가 끝나면 정리 노트를 한 번에 올려 검토받고, (3) 단계가 바뀔 때는 새 대화를 연다. 새 대화도 CLAUDE.md 와 QNA.md 를 읽고 이어 간다. 정리 노트는 `log/M1_notes.md` 로 저장하고 AI 검토 4가지를 덧붙였다 (정상 전류 0.119 A, V4는 최대−최소, V6는 missed=0 으로 확인되지 않음, 주기는 닫힌 루프 시정수와 비교).
- 관련 파일: `log/M1_notes.md`
- 내 말로 한 줄:

### Q004. 이 프로젝트에서 가장 잘 배워야 할 것은 포인터가 아닌가
- 날짜: 2026-11-11
- 단계: M1
- 내가 한 질문: "내가 이 프로젝트에서 가장 잘 배우고 가야할것이 난 포인터인거 같아, 메모리 구조부터 시스템 동작에 가장 영향을 미치는거 같거든 어때"
- 왜 막혔나: (방향 질문) 포인터가 약하다는 것을 알고 있고, 무엇을 중심으로 공부할지 정하려 했다.
- 답 요약: 방향은 맞다. 다만 목표를 "포인터 문법"이 아니라 "메모리 모델"(값이 어디 살고, 얼마나 오래 살고, 누가 바꾸는가)로 잡으면 펌웨어 버그와 직접 이어진다. 이 프로젝트의 버그 다수(M5 Q4 적분 사라짐, M8 오버플로, M9 windup)가 이 세 질문에서 나온다. 단계별 포인터 실습 경로를 `docs/c_notes.md` 11절에 추가했다. 힙(malloc)과 스택 프레임은 이 프로젝트 범위 밖이라 시스템프로그래밍으로 남긴다.
- 관련 파일: `docs/c_notes.md` 11절
- 내 말로 한 줄:

### Q005. 메모리 모델을 깊이 팔 자료와 프로젝트 이후 펌웨어 공부 자료
- 날짜: 2026-11-11
- 단계: 심화
- 내가 한 질문: "메모리모델 보충해서 공부할 수 있게 자료 만들어둬 ... 프로젝트는 전체적으로 내가 전자공학 2학년까지 배운거 집대성으로 하는 느낌이고 깊이 파는 분야 하나 만들고싶어 ... 펌웨어쪽으로 가고싶은건 지금은 확실하니 이쪽 관련해서 프로젝트 이후 더 깊이 공부할 자료 뒤에 만들어둬 프로젝트는 빠르게 익숙해지는 느낌으로 보고 뒷쪽 심화파트 제대로할게"
- 왜 막혔나: (방향 결정) 프로젝트는 넓게, 하나는 깊게 가고 싶었다. 깊이 팔 주제를 메모리로 정했다.
- 답 요약: `advanced/` 폴더를 만들었다. A1 메모리 지도, A2 바이트·포인터 연산·패딩, A3 스택, A4 힙과 고정 블록 풀, A5 레지스터와 비트 조작, A6 인터럽트와 경쟁 상태. 각 장은 실행되는 실습(`python run.py lab ...`)과 "먼저 예상 → 실행 → 설명 → 질문 → 직접 해 볼 것" 순서다. A7은 프로젝트 이후 로드맵(책, 실제 보드, RTOS, 다음 프로젝트 후보).
- 관련 파일: `advanced/README.md`, Q004 에 이어서
- 내 말로 한 줄:

### Q006. 코드 공부가 어렵다. 구조 중심으로 가고 싶다
- 날짜: 2026-11-11
- 단계: 전체
- 내가 한 질문: "손계산까진 잘따라가는데 이 이후는 너무 코딩쪽이라서 안 익숙해서 그런가 되게 어렵게 느껴져, 아키텍쳐 구성능력을 키우는게 중요할거 같은데 세세한 코드 보는거보단 아키텍쳐위주로 공부하고싶다 ... 실험이나 가설들을 설계하고 아키텍쳐적으로 구상해서 ai통해 코드 짜고 검증하는 프로세스로 가고싶어 메모리구조도 이런느낌으로 ... 정성적으로 흐름이해할 수 있을정도만 되면 돼"
- 왜 막혔나: 손 계산(M1)까지는 따라갔지만 코드를 한 줄씩 읽는 단계(M2 이후)가 익숙하지 않아 어렵게 느껴졌다. 쓸 수 있는 시간도 적다.
- 답 요약: 공부 방식을 구조 중심으로 바꿨다. `docs/ARCHITECTURE.md`(부품과 책임, 상태, 세 개의 시계, 맞바꿈, 문제 지도), `docs/FAST_TRACK.md`(가설 → 실험 → 판정으로 전체를 도는 표, AI에게 줄 실험 카드), `advanced/OVERVIEW.md`(메모리 구조 정성적 개요와 설계 규칙 표, AI 코드 검토 체크리스트)를 추가했다. 역할은 "내가 설계하고 판정, AI가 구현"으로 바꿨다. 단, 헤더 파일(약속)은 읽을 수 있어야 하고, AI의 코드는 손 계산·일부러 틀리게 하기·경계 확인의 세 가지 증거로 판정한다.
- 관련 파일: `docs/ARCHITECTURE.md`, `docs/FAST_TRACK.md`, `advanced/OVERVIEW.md`, `log/EXPERIMENT_TEMPLATE.md`, Q004·Q005 에 이어서

## M10에서 이 파일을 쓰는 법

1. 표를 분류별로 세어 본다. 어느 분류에 질문이 몰렸는가? 그것이 내가 가장 약했던 부분이다.
2. 상태가 `남김` 인 것들을 모은다. 그것이 "앞으로 배울 것"의 근거다.
3. 같은 주제로 여러 번 물은 것을 찾는다 (예: 포인터를 세 번 물었다). 처음 질문과 마지막 질문을 나란히 놓으면 "어떻게 이해가 깊어졌는지"가 보인다.
