# 질문 기록

공부하면서 AI에게 한 질문과, 그것이 어떻게 풀렸는지를 모아 두는 파일.
M10에서 "어떤 어려움을 겪었고 어떻게 해결했는가"를 쓸 때의 재료다.

## 쓰는 규칙

- **AI가 적는다**: 내가 채팅에서 질문할 때마다 AI가 아래 표에 한 줄을 더하고, 아래쪽에 상세 항목을 추가한 뒤 GitHub에 올린다.
- **내가 적는다**: 상세 항목의 "내 말로 한 줄"은 비워 둔다. 이해한 뒤에 내가 직접 채운다. 여기가 채워져야 그 질문이 "해결"이다.
- 질문은 내가 한 말 그대로에 가깝게 적는다. 다듬지 않는다. 무엇을 몰랐는지가 그대로 남아야 한다.
- 상태: `해결` (내 말로 설명할 수 있다) / `부분` (답은 들었지만 아직 다 이해하지 못했다) / `남김` (지금 지식으로는 풀 수 없어 앞으로 배울 것으로 남긴다)

## 상세

### Q001. 내 컴퓨터가 꺼져 있어도 클라우드에서 GitHub에 파일을 만들 수 있는가
- 날짜: 2026-11-10
- 단계: M0
- 내가 한 질문: "지금은 컴퓨터 안 켜져 연결 안 돼 있잖아. 그러면 클라우드랑 연결되고 내가 지금 연결해놓은 깃허브랑 연결돼서 거기 안에서 파일 만들 수 있는 거지."
- 왜 막혔나: 작업이 어디서 실행되는지(내 컴퓨터인지 클라우드인지) 몰랐다.
- 답 요약: AI 세션은 클라우드의 임시 컴퓨터에서 돈다. 거기에 GitHub 저장소가 복제되어 있어서, 파일을 만들고 commit·push 하면 GitHub에 남는다. 임시 컴퓨터는 세션이 끝나면 사라지므로 push 한 것만 남는다. 내 컴퓨터에서는 `git pull` 로 받아 온다.
- 관련 파일: `docs/M0_setup.md`

### Q002. GitHub에 올렸다는 파일이 왜 안 보이는가
- 날짜: 2026-11-11
- 단계: M0
- 내가 한 질문: "왜 안보이지 체크해"
- 왜 막혔나: git의 브랜치 개념을 몰랐다. GitHub 첫 화면은 `main` 브랜치만 보여 준다.
- 답 요약: 파일은 전부 작업 브랜치 `ccr-a795ff36-u6wtnd` 에 올라가 있고, `main` 에는 처음 만든 README 하나뿐이다. 브랜치는 같은 저장소 안의 "다른 버전의 폴더"와 같다. GitHub 화면 왼쪽 위의 브랜치 선택 버튼에서 작업 브랜치를 고르면 보인다. 작업 브랜치를 `main` 에 합치면(merge, 보통 PR로 한다) 첫 화면에서도 보인다.
- 관련 파일: Q001 에 이어서

## M10에서 이 파일을 쓰는 법

1. 표를 분류별로 세어 본다. 어느 분류에 질문이 몰렸는가? 그것이 내가 가장 약했던 부분이다.
2. 상태가 `남김` 인 것들을 모은다. 그것이 "앞으로 배울 것"의 근거다.
3. 같은 주제로 여러 번 물은 것을 찾는다 (예: 포인터를 세 번 물었다). 처음 질문과 마지막 질문을 나란히 놓으면 "어떻게 이해가 깊어졌는지"가 보인다.
